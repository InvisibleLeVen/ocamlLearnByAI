## E11-1 · fold_left 的类型与求值

已知：

```ocaml
let rec fold_left f acc lst =
  match lst with
  | [] -> acc
  | h :: t -> fold_left f (f acc h) t;;
```

要求：

1. 写出 `fold_left` 的类型；
2. 计算 `fold_left (fun acc x -> acc - x) 0 [1; 2; 3]` 的值；
3. 展开求值过程，说明为什么是左结合；
4. 说明 `fold_left` 的递归调用是否在尾位置，为什么。

用户答案：1. `('a -> 'b -> 'b) -> 'a list -> 'b` 2. `-6` 3. `((0 - 1) - 2) - 3`，因为会先 `f h acc` 求值，然后把结果作为 `acc` 对 `t` 进行递归求值。4. 递归调用在尾位置，因为递归 case 的 `fold_left` 是最后调用的，参数表达式的求值先于函数调用。

老师反馈：第 2 问正确；第 3 问的展开式正确，但代码中是 `f acc h`，不是 `f h acc`，顺序需改正后重述；第 4 问正确（参数先求值，随后尾调用）。第 1 问类型错误：`fold_left` 有三个参数 `f, acc, lst`，返回值与 `acc` 同类型；`('a -> 'b -> 'b)` 和 `'a list` 的形状混淆了累加器与元素。请按以下线索重写：设 `acc : r`，`lst : e list`；`h :: t` 给出 `h : e`、`t : e list`；`f acc h` 必须能作为新的 `acc`，所以 `f : r -> e -> r`；递归调用返回 `r`。评分：70/100，补答正确后记满分。

第一次订正（2026-11-13）：`('a -> 'b -> 'a) -> 'a -> 'b list`，并说明“`f` 第一个参数 `'b` 是 `acc`，第二个参数 `'a` 是元素类型；先对 0 和 1 调用 `f` 得 -1，再对 -1 和 2 调用得 -3”。第 3 问的累加过程已正确使用 `f acc h`。类型还差最后一段返回类型：`fold_left f acc lst` 的返回值与 `acc` 同类型，应再接 `-> 'a`；变量映射也写反了——`f : 'a -> 'b -> 'a` 的第一个参数是 `'a`（`acc`），第二个是 `'b`（元素），返回 `'a`。评分：85/100，补全后记满分。

第二次订正（2026-11-13）：`('a -> 'b -> 'a) -> 'a -> 'b list -> 'a`；`f` 第一个参数是 `acc`，第二个参数是 `'b list` 中的元素。类型完整，变量映射正确。E11-1 补至 100/100。

## E11-2 · 尾递归的 sum_to

第 5B 课的 `sum_to`：

```ocaml
let rec sum_to n =
  if n = 0 then 0
  else n + sum_to (n - 1);;
```

要求：

1. 写一个尾递归版本 `sum_to_acc n acc`；
2. 写出 `sum_to_acc` 的类型；
3. 计算 `sum_to_acc 4 0` 的值；
4. 说明 `acc` 在每一层保存的是什么，以及为什么递归调用在尾位置。

用户答案：1. `let rec sum_to_acc n acc = match n with | 0 -> acc | x -> sum_to_acc (n - 1) (acc + x);;` 2. `int -> int -> int` 3. `10` 4. `acc` 每层保存的是每层 `x` 累计的结果，因为 `sum_to_acc` 是递归 case 最后调用的。

老师反馈：定义、类型、值 10 均正确；用整数模式 `0 | x` 合法，也可以写成 `if n = 0`。`acc` 保存已处理部分的累计和；递归调用是分支的整个结果，所以在尾位置。评分：100/100。

## E11-3 · 用 fold_left 反转列表

要求：

1. 用 `fold_left` 写 `rev : 'a list -> 'a list`；
2. 计算 `rev [1; 2; 3]` 的值；
3. 展开 `rev [1; 2; 3]` 的累加过程；
4. 说明为什么结果顺序和原列表相反。

用户答案：1. `let rev lst = fold_left (fun acc x -> x :: acc) [] lst;;` 2. `[3; 2; 1]` 3. `3 :: (2 :: (1 :: []))` 4. 因为每次处理先调用 `f`，把 `f` 返回值作为 `acc` 后调用递归；从左到右每次都把 `acc` 结果与 `h` 拼起来，`h :: acc`，后面的元素会出现在最前面。

老师反馈：定义、值、结构和理由均正确。实际运行 `rev [1;2;3] = [3;2;1]`；累加过程是 `[] → [1] → [2;1] → [3;2;1]`。评分：100/100。

## E11-4 · 判断尾位置

判断下列递归调用是否在尾位置，并说明理由：

1. `let rec f n = if n = 0 then 0 else f (n - 1) + 1`
2. `let rec f n acc = if n = 0 then acc else f (n - 1) (acc + n)`
3. `let rec f lst = match lst with [] -> 0 | h :: t -> h + f t`
4. `let rec f lst acc = match lst with [] -> acc | h :: t -> f t (acc + h)`

用户答案：1. 不是，`+ 1` 才是尾位置 2. 是，`f` 调用在递归 case 是最后面的 3. 不是，`h +` 在尾位置 4. 是，`f t (acc + h)` 在尾位置。

老师反馈：四问判断均正确。第 1、3 问中 `+ 1` / `h +` 是递归返回后的 pending work，所以不是尾位置；第 2、4 问的递归调用就是分支的整个结果，是尾位置。评分：100/100。
