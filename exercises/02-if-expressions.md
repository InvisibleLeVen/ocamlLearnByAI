## E02-1 · 结果与值的区别

```ocaml
if 5 > 2 then 10 else 20
```

这个表达式的类型、求值结果分别是什么？整个 if 代码片段本身已经是一个值吗？说明理由。

用户答案：类型是 int，求值结果是 10；if 代码本身不是值，而是表达式，解释器 evaluate 之后才是值。

老师反馈：类型、结果以及“表达式 vs 值”的区分均正确。整段 if 是 int 类型的表达式，需要先求值条件再选分支；求值后得到的 10 才是值。判定：通过。

## E02-2 · 分支类型

```ocaml
if true then 10 else 2.5
```

能通过类型检查吗？条件已经写成 true，会不会改变你的判断？说明理由。

用户答案：不能通过类型检查；没懂“条件写成 true 会不会影响判断”是什么意思，判断什么。

老师反馈：结论正确，理由待补。这里“判断”指类型检查能否通过，以及是否会因为条件是常量 true 就以为 else 分支可以忽略。类型检查器不根据条件的值做取舍，then 和 else 两个分支都会被检查：10 是 int、2.5 是 float，类型不一致，所以拒绝。运行时的确只会求值 10，但程序在运行前就已被类型检查拒绝。对照 `if true then 10 else 20`：两分支同为 int，可以通过，结果为 10。判定：结论正确，理由待 E02-R1 验证。

## E02-R1 · 常量条件与类型检查

```ocaml
if false then 10 else 2.5
```

能通过类型检查吗？条件写成 false 是否意味着只需检查 else 分支？说明理由。

用户答案：不能通过类型检查，if表达式 then后面的位置和else后面位置期望值的类型应该是相同的。条件写成false不止会只检查else分支，类型检查会检查两个分支。

老师反馈：正确。then 与 else 两个分支都必须是同一类型；`10 : int`、`2.5 : float`，不一致，因此拒绝。类型检查不根据条件的常量值跳过任一分支；条件写成 false 也一样。表述上“不止会只检查 else 分支”可改为“不是只检查 else 分支，而是两个分支都检查”。判定：通过。

## E02-3 · 条件的类型

```ocaml
if 1 then 10 else 20
```

能通过类型检查吗？说明理由。

用户答案：不能通过类型检查，if 后面值的期望类型是 bool，1 是 int。

老师反馈：正确。条件位置（`if` 与 `then` 之间）要求 bool，而 1 的类型是 int，不匹配。判定：通过。
