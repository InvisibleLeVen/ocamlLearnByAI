## 1. 什么是尾调用

如果一个函数调用是当前函数“最后要做的事”，它的结果直接作为当前函数的结果返回，那么这个调用位于**尾位置**（tail position）。

对照：

```ocaml
let f x = g x          (* g x 在尾位置 *)
let f x = 1 + g x      (* g x 不在尾位置：返回后还要加 1 *)
```

**尾递归**是尾调用的特例：函数在尾位置调用自己。

## 2. 非尾递归的阶乘

```ocaml
let rec fact n =
  if n = 0 then 1
  else n * fact (n - 1);;
```

`fact (n - 1)` 返回后，还要把结果乘以 `n`，所以递归调用不在尾位置。

调用过程中，每一层都要等下一层返回，然后继续做乘法；栈帧会随 `n` 增大而累积。

## 3. 用累加器改成尾递归

```ocaml
let rec fact_acc n acc =
  if n = 0 then acc
  else fact_acc (n - 1) (n * acc);;
```

- `acc` 是**累加器**，保存已经算出的部分结果；
- 递归调用 `fact_acc (n - 1) (n * acc)` 是 else 分支的最后一步；
- 返回后没有待做的乘法，所以它在尾位置。

求值 `fact_acc 4 1`：

```text
fact_acc 4 1
= fact_acc 3 (4 * 1) = fact_acc 3 4
= fact_acc 2 (3 * 4) = fact_acc 2 12
= fact_acc 1 (2 * 12) = fact_acc 1 24
= fact_acc 0 (1 * 24) = fact_acc 0 24
= 24
```

外层再包一个固定初始值的函数：

```ocaml
let fact n = fact_acc n 1;;
```

## 4. 尾递归为什么有用

非尾递归的 `fact` 需要保存每一层的“还没做的乘法”，栈深度随 `n` 增长；`n` 很大时可能栈溢出。

尾递归版本在尾位置调用自己，OCaml 实现会做**尾调用优化**，复用当前栈帧，因此栈空间不随递归深度增长。

注意：

- 尾递归不会把时间复杂度从 O(n) 变成 O(1)，它主要解决栈空间问题；
- 不是所有函数都自然尾递归，有时需要累加器或其他技巧；
- 尾调用优化依赖调用确实位于尾位置；有 pending work 就不是尾调用。

## 5. 另一个例子：pow2 的尾递归版

```ocaml
let rec pow2_acc n acc =
  if n = 0 then acc
  else pow2_acc (n - 1) (2 * acc);;
```

类型：`int -> int -> int`。

```ocaml
let pow2 n = pow2_acc n 1;;
```

求值 `pow2_acc 3 1`：

```text
pow2_acc 3 1
= pow2_acc 2 2
= pow2_acc 1 4
= pow2_acc 0 8
= 8
```

## 6. 如何判断是否在尾位置

问自己：**递归调用返回之后，还有没有事情要做？**

| 代码 | 是否尾位置 | 原因 |
| --- | --- | --- |
| `f (n - 1)` | 是 | 返回值直接作为结果 |
| `1 + f (n - 1)` | 否 | 返回后还要加 1 |
| `n * f (n - 1)` | 否 | 返回后还要乘 n |
| `f (n - 1) + 1` | 否 | 返回后还要加 1 |
| `g (f (n - 1))` | 否 | f 的结果还要传给 g |

`if` 和 `match` 的分支也一样：如果分支的结果直接就是递归调用，那么该调用在尾位置。

## 7. 常见错误

| 错误 | 结果 |
| --- | --- |
| 累加器初值错，如 `fact_acc 3 0` | 结果变成 0 |
| 非交换运算的累加顺序写反 | 结果顺序错误 |
| 以为“递归”就是“尾递归” | 实际仍有 pending work，栈会增长 |
| 忘记 base case | 无限递归 |

对于加法、乘法，顺序不影响结果；但对于字符串拼接、列表拼接等非交换操作，累加器更新的顺序会影响结果。

## 8. 与 C++ / Python 对比

| 项目 | C++ / Python | OCaml |
| --- | --- | --- |
| 循环 | `for` / `while` | 常用尾递归模拟循环 |
| 尾调用优化 | C++ 视编译器；Python 通常不做 | OCaml 实现会优化尾调用 |
| 深递归风险 | Python 有递归深度限制 | 尾递归可避免栈增长；非尾递归仍可能溢出 |

## 9. 本课要点

1. 尾调用：调用的结果直接作为当前函数的结果。
2. 尾递归：在尾位置调用自己。
3. 有 pending work（如 `n * ...`、`1 + ...`）就不是尾递归。
4. 用累加器把部分结果带到下一次调用，可把某些递归改成尾递归。
5. 尾递归主要节省栈空间，不改变时间复杂度。
6. 累加器初值和更新顺序要结合具体运算确定。
