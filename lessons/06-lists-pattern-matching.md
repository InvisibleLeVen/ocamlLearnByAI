## 1. 列表

列表用方括号和分号书写：

```ocaml
[]
[1; 2; 3]
[1.0; 2.5]
```

列表元素必须是同一类型：

- `[1; 2; 3] : int list`
- `[1.0; 2.5] : float list`
- `[] : 'a list`（空列表可以是任意元素类型）
- `[1; "a"]` 类型错误：int 与 string 不一致

`::` 是“把元素放到列表前面”的构造符（cons）：

```ocaml
1 :: [2; 3]      (* [1; 2; 3] *)
1 :: 2 :: []     (* [1; 2] *)
```

`::` 右结合，所以 `1 :: 2 :: []` 等价于 `1 :: (2 :: [])`。`[1; 2; 3]` 只是 `1 :: 2 :: 3 :: []` 的简写。

## 2. match 表达式

```ocaml
match 表达式 with
| 模式1 -> 结果1
| 模式2 -> 结果2
```

特点：

- `match` 是表达式，整体有类型和值；
- 各分支的结果类型必须一致；
- 从上到下匹配，**第一个匹配的分支**生效；
- 分支之间没有 C++ `switch` 的 fallthrough；
- 模式可以解构数据，比如取出列表的头和尾。

常见模式：

| 模式 | 含义 |
| --- | --- |
| `[]` | 空列表 |
| `h :: t` | 头为 h、尾为 t 的非空列表 |
| `_` | 任意值，不绑定名字 |
| `0` | 整数 0 |
| `x` | 任意值，绑定到 x |

## 3. 递归处理列表

```ocaml
let rec sum xs =
  match xs with
  | [] -> 0
  | h :: t -> h + sum t;;
```

类型：`int list -> int`。

求值 `sum [10; 20; 30]`：

```text
sum [10; 20; 30]
= 10 + sum [20; 30]
= 10 + (20 + sum [30])
= 10 + (20 + (30 + sum []))
= 10 + (20 + (30 + 0))
= 60
```

- `[]` 是 base case；
- `h :: t` 把列表拆成头和尾，再递归处理尾部 `t`；
- 每次递归列表都变短，最终到达 `[]`。

## 4. 另一个例子：乘积

```ocaml
let rec product xs =
  match xs with
  | [] -> 1
  | h :: t -> h * product t;;
```

类型：`int list -> int`。

- base case 返回 `1`，因为 1 是乘法的单位元；
- 非空时把 `h` 乘上尾部的乘积。

同样的结构可以用于：

- 求长度：空列表返回 `0`，非空时 `1 + ...`；
- 统计满足条件的元素：空列表返回 `0`，非空时根据 `if` 决定加 `1` 还是加 `0`。

## 5. match 与整数模式

`match` 也可以匹配整数，代替一部分 if：

```ocaml
let rec fact n =
  match n with
  | 0 -> 1
  | _ -> n * fact (n - 1);;
```

`0` 匹配 base case，`_` 捕获其余整数。注意模式顺序：`_` 会匹配一切，如果放在前面，后面的分支就永远用不到。

`fact (-1)` 仍然不会终止，因为 `_` 分支一直递归，永远到不了 `0`。

## 6. 匹配穷尽性

OCaml 会检查模式是否覆盖所有情况。比如：

```ocaml
let first_or_zero xs =
  match xs with
  | h :: _ -> h;;
```

这个函数只处理非空列表，编译时会有“匹配不穷尽”的警告（Warning 8）。在交互环境或默认编译下，它通常仍会编译通过；但运行 `first_or_zero []` 时会抛出 `Match_failure`。

所以：

- 类型检查通过 ≠ 所有输入都有分支处理；
- 看到“不穷尽”的警告要认真处理；
- 列表匹配通常写 `[]` 和 `h :: t` 两个分支来覆盖全部情况。

有些构建配置会把警告当错误；是否阻止编译取决于编译选项。

## 7. 与 C++ / Python 对比

| 项目 | C++ `switch` | OCaml `match` |
| --- | --- | --- |
| 是否表达式 | 语句 | 表达式，有值 |
| fallthrough | 默认会 | 不会，每个分支独立 |
| 模式能力 | 基本是常量 | 可解构列表、元组等 |
| 穷尽性 | 通常不强制 | 编译器警告 |
| 默认分支 | `default` | `_` |

## 8. 本课要点

1. 列表是同质序列，`[]` 为空，`h :: t` 分为头和尾。
2. `match` 是表达式，按顺序匹配，第一个匹配的分支生效。
3. 列表递归通常用 `[]` 和 `h :: t` 两个模式。
4. `_` 是通配符，不绑定名字。
5. 匹配不穷尽时编译器警告，运行时可能 `Match_failure`。
